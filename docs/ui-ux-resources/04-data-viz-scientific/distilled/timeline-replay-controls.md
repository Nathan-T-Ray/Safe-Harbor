# Timeline, replay/playback and provenance UI

Sources: WAI-ARIA APG Slider pattern (incl. Media Seek example) https://www.w3.org/WAI/ARIA/apg/patterns/slider/, MDN prefers-reduced-motion https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion, vis-timeline docs https://visjs.github.io/vis-timeline/docs/timeline/, Trrack https://github.com/Trrack/trrackjs + https://apps.vdl.sci.utah.edu/trrack, W3C PROV https://www.w3.org/TR/prov-overview/

## Scrubber (seek slider): keyboard and ARIA contract
- The thumb uses `role="slider"` with `aria-valuemin`, `aria-valuemax`, `aria-valuenow` (the event index or ms), and a readable **`aria-valuetext`** such as "Event 12 of 40, 14:03:22, evidence recorded". Give it a label through `aria-labelledby` or `aria-label`.
- Keys: Left/Down = previous event, Right/Up = next event, Home = first, End = last. Optionally, PageUp/PageDown jump by 10 events or to the next stage boundary.
- Step by **event**, not by pixel or ms. Replay is discrete: every step should land on a real recorded event.

## Transport controls
- Play/Pause is one toggle button with `aria-pressed` or a changing label. There are separate Step back/Step forward buttons, a speed selector (0.5×/1×/2×/4×), and a "Jump to live" button that appears whenever the view is not live.
- **Replay vs live must be obvious.** Show a persistent banner or badge ("REPLAY — viewing state at 14:03:22") with a distinct style. While replaying, every panel (conclusion, graph, genome) shows the state *as of that time*, and never mixes it with the latest state.
- Announce step changes in a polite `aria-live` region. Don't announce every tick during playback. Announce on pause or on stage changes.

## Follow camera
- "Follow" means the graph or genome view moves to the entity the current event touches. When the user pans or zooms by hand, **turn follow off automatically** and show that it's off ("Follow: off — resume").
- Animate movement with a short `duration` in `fitView`/`setCenter`. Under `prefers-reduced-motion: reduce`, jump instead of animating and pause auto-play.
- Don't move keyboard focus to the followed node. Moving the view and moving focus are separate actions.

## Timeline rendering
- Events sit on a time axis with lanes per actor or worker, or with stage bands. Mark the current position (playhead) and "now" separately (vis-timeline has both a current-time and a custom-time marker).
- Show gaps honestly. Long idle periods can be compressed, but the compression must be visible (a broken-axis marker).
- Cluster dense bursts and expand them when zoomed in. Each event row shows time, actor, action and a link to its record.

## Provenance and audit trail
- Treat the event log as a provenance graph (Trrack model: a tree of states you can navigate). Every state records the action, who did it, and when, and any earlier state can be restored for viewing.
- Use PROV terms consistently in drawers: **Entity** (evidence artifact), **Activity** (task/run), **Agent** (worker/model/human). Examples: "generated by", "used", "was attributed to".
- Records are immutable in the UI. Corrections show as new events that supersede old ones, with the older record still reachable. Show hashes or ids with copy buttons for reproducibility.
- Replay must be deterministic: the same event index always produces the same rendered state, including graph layout (see `react-flow-v12-dag-ux.md`).
