# Communicating uncertainty and status honestly

## Key research points (paraphrased)
- People read a mark drawn at a position as exact. Showing no uncertainty therefore suggests certainty, even when nothing was claimed.
- Error bars and intervals are compact but need expert knowledge to read. For mixed audiences (presentation mode), frequency framing or plain-language statements work better.
- If the design emphasises a point estimate, viewers tend to ignore the uncertainty around it. Don't make the headline number or badge bigger than its qualifier.
- Qualitative confidence wording ("limited evidence") changes decisions. Pick a fixed vocabulary and use it everywhere.

## Rules for Safe-Harbor's three axes
Keep **screen status**, **evidence status** and **freshness** as three separate, labelled fields. Never merge them into one colour or score.

| Axis | Suggested states (fixed vocabulary) | Visual |
|---|---|---|
| Screen status | not screened · screened: no flag raised · screened: flagged · screen failed | Text chip plus icon |
| Evidence status | none recorded · incomplete (n of m required) · complete · conflicting | Segmented progress bar (n of m) with text |
| Freshness | current · stale (reason, age) · unknown | Timestamp plus relative age |

1. **Never say or imply "safe", "benign" or "cleared".** Say what was checked, for example: "No flag raised by the checks that ran (4 of 6)."
2. **Missing counts as incomplete, not negative.** Show absent evidence as a hollow or neutral slot labelled "not yet collected". Never show it as green, a tick, or "0 issues".
3. **Screen status comes first.** "Screened: no flag raised" alongside "Evidence: incomplete" must not look reassuring overall. The page summary should reflect the weakest axis.
4. **Colour is never the only channel.** Pair every colour with text and an icon. Use a colour-blind-safe palette (ColorBrewer). Avoid red/green as the only contrast. Keep green out of anything short of "complete and current", and even then it only describes evidence completeness, not safety.
5. **Show the denominator.** "3 of 7 required evidence items" is honest. "3 items" hides the gap.
6. **Show where every claim comes from.** Each status should link to the evidence records, run id and timestamp behind it. W3C PROV's Entity / Activity / Agent terms work well for drawer labels ("generated by task X, run by worker Y, at T").
7. **Stale data looks stale.** Dim or hatch it and name the reason ("reference changed since run"). Don't hide it.
8. **Numeric uncertainty** (scores, overlaps): show an interval or quantile dots next to the point estimate, at equal visual weight (ggdist vocabulary). Round to a precision the data supports.
9. **Presentation mode** carries the same caveats in larger type. Qualifiers are never removed to "clean up" slides.

## Copy checklist for a fixer
- [ ] No "safe", "clean", "passed" (unless it names the specific check), "no risk".
- [ ] Each empty state says *why* it is empty: not run, running, failed, or truly nothing found.
- [ ] Each badge has a tooltip or drawer entry with the definition and the source record.
